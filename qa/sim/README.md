# 자동 플레이테스트

`우리 가족`의 qa/sim 과 같은 방식이다. 테스트는 두 종류가 있다.

| | `npm run qa:story` | `npm run qa:play` |
|---|---|---|
| 무엇을 | 게임 엔진만 성향별 1,000판 | 실제 브라우저에서 사람처럼 1판 |
| 시간 | 약 30초 | 15~30분 (`--read-speed`로 조절) |
| 찾는 것 | 이야기·밸런스: 복선 미회수, 엔딩 모순, 도달 불가 이벤트, 반복 피로, 사라지는 정산 | 플레이: 페이지 오류, 길 막힘, 안내가 안 뜨는 지점, 전화가 안 울림, 너무 먼 길, FPS, 모바일 화면 겹침 |
| 결과 | `qa/reports/story-<시각>.md` | `qa/sim/reports/<시각>-<성향>/report.html` |

## 이야기 점검 (`qa/story-sim.mjs`)

화면 없이 `gameReducer`를 그대로 돌린다. 성향 4가지(아무거나 / 다지르기 / 조심파 / 게이지관리).

- **복선 미회수**: 선택으로 얻은 플래그가 이후 이벤트 조건, 엔딩 후일담(`src/data/epilogue.json`), 엔진 어디에서도 안 쓰임
- **후속 이야기 회수율**: 선행 선택을 한 판 중 후속 이벤트를 실제로 본 비율. 35% 미만이면 주의
- **엔딩 모순**: 엔딩 본문이 "아무도 모른다"인데 누군가에게 말했거나, "회사에 다닌다"인데 퇴사한 경우
- **도달 불가 / 희귀 이벤트**, **반복 피로**(한 판에 같은 이벤트를 너무 자주 봄)
- **무의미한 선택지**: 다른 선택지보다 모든 수치가 나쁜 선택. 이야기상 의도일 수 있어 참고로만 표시

## 플레이 봇 (`qa/sim/play.mjs`)

- 타이틀에서 **QR을 찍는다**를 누르고 엔딩까지 한 번에 간다.
- 입력은 실제 키보드뿐이다. 방향키로 몸을 돌리고 W로 걷고 Shift로 달리고, 안내가 뜨면 E. 대화창은 숫자키나 클릭으로 고르고 Space나 클릭으로 넘긴다.
- 길은 게임의 충돌 판정으로 만든 격자에서 찾는다. 막히면 뒤로 물러나 옆으로 비키고 다시 찾는다. 4번 실패하면 순간이동하고 **구조**로 기록한다 — 사람이 막힐 수 있는 곳이다.
- 대화는 글자 수에 비례한 시간만큼 읽는다. 선택은 **사람이 화면에서 보는 것**(선택지 문장, 금액 표시)만으로 한다. 멘탈·의심도 변화는 고른 뒤에야 안다.
- 끝나면 휴대폰 크기(390×844)로 한 번 더 열어 UI 겹침·가로 넘침을 검사한다.

게임 상태는 `probe.js`로 **읽기만** 한다(위치, 화살표가 가리키는 곳, 안내 문구). 테스트 중에만 브라우저에 주입된다.

```sh
npm run qa:play -- --persona casual
npm run qa:play -- --persona casual,explorer,rusher --read-speed 8
```

처음 한 번 브라우저가 없다는 오류가 나오면 `qa/sim/run.sh --install`.

| 옵션 | 설명 |
|---|---|
| `--persona` | `casual`(기본) · `explorer`(천천히 읽고 돈을 아끼고 자주 딴 데로 샘) · `rusher`(계속 달리고 대충 읽고 큰돈을 잘 씀). 쉼표로 연속 실행 |
| `--headed` | 브라우저 창을 띄워 봇이 플레이하는 모습을 본다 |
| `--read-speed 8` | 읽는 속도 배수. 클수록 빨리 끝난다 |
| `--until-day 60` | D+60에서 멈춘다 |
| `--seed 42` | 게임 난수와 봇의 선택을 고정해 같은 판을 재현한다 |
| `--sound` | 소리를 켠다(기본 음소거) |
| `--url https://...` | 로컬 대신 배포된 사이트를 검사 |
| `--no-assist` | 막히면 순간이동하지 않고 중단 |
| `--no-mobile-check` | 모바일 화면 검사 생략 |
| `--max-minutes 40` | 제한 시간 |

## 한계

- 봇은 화면을 "보지" 않는다. 너무 어두운 장면이나 헷갈리는 안내 문구처럼 사람 눈에만 보이는 문제는 스크린샷으로 직접 확인해야 한다.
- 봇은 노란 화살표가 가리키는 목표를 바로 안다. 길을 헤매는 정도는 `explorer`의 딴짓으로 일부만 흉내 낸다.
- 시점 고정(Pointer Lock) 대신 방향키로 몸을 돌린다.
